# 领域约定

国际友城合作关系图谱围绕**行政实体、友好关系、合作计划与合作事项**保存可核对的业务记录。
一切当前状态都由追加式事件日志重放得到，历史记录不就地修改，保证更名、合并、暂停、终止等过程长期可追溯。

## 1. 稳定标识

| 对象 | 前缀 | 示例 |
| --- | --- | --- |
| 行政实体（国家/省州/城市） | `ENT-` | `ENT-SHA01` |
| 实体名称（含历史名称） | `NAM-` | `NAM-OLD01` |
| 友好关系 | `REL-` | `REL-SHAOSA` |
| 路线图 / 交往计划 | `PLN-` | `PLN-CNJP01` |
| 法定批准记录 | `APR-` | `APR-SHA01` |
| 关系文本版本 | `TXT-` | `TXT-ZH01` |
| 承诺事项 | `CMT-` | `CMT-TOUR01` |
| 交流活动 | `ACT-` | `ACT-092101` |
| 事件 | `EVT-`（服务端）/ 来源自有编号 | `EVT-2026-000001` |

标识一经分配**不得复用**。行政区更名不换标识，只追加名称；合并时旧标识保留，
沿继受链（`merged_into`）可解析到现行实体。名称按 BCP 47 语言标签多语保存
（`{"zh": "…", "en": "…"}`），历史名称随实体永久保留，支持按旧名检索。

## 2. 事件与交换信封

每条事实是一个事件信封（见 `contracts/event.example.json`）：

- `event_id`：全局唯一，重复提交时**幂等**；同标识但内容/来源/序号不一致按冲突拒绝。
- `source` + `source_sequence`：来源序号只在同一来源内严格递增；留空时由服务端在写锁内自动分配。
- `occurred_at`：**带偏移量的 ISO 8601**。接收方保留原始字符串，不用到达时间覆盖；
  解析结果仅用于排序与绝对时刻比较。
- `payload_digest`：`sha256:<hex>`，对载荷 JSON 的确定性编码（键名排序）计算，
  落盘前与重放时逐行复核，任何篡改都会导致打开/重放失败。
- `payload.type`：载荷鉴别字段，全部类型见 `internal/events`。

写入路径固定为：幂等探测 → 投影业务校验 → 追加日志并 fsync → 更新内存投影。
服务重启时重放日志重建全部状态与来源序号水位。

## 3. 关系生命周期与法定批准

```
intended ──双边批准齐备 + conclude──▶ concluded ──suspend──▶ suspended
   ▲                                    │  ▲                    │
   │（旧关系终止后允许登记新的意向对）     │  └──────resume────────┘
   └────────────────────────────────────┼─terminate─▶ terminated
                                        └─terminate─▶ terminated
```

- 状态只有四态：`intended`（意向）、`concluded`（正式缔结）、`suspended`（暂停）、`terminated`（终止）。
- **正式缔结的前置条件是双方法定批准齐备**：两侧各有一条最新决定为 `approved` 的记录
  （`side=a/b`，含批准机关、决定日期、文书摘要）。一侧批准、事后否决都不能缔结。
- 每次状态变迁进入关系历史（含时间与事由），终止后承诺、文本、活动仍可查阅。

## 4. 重复上报不得创建第二对关系

关系两侧是**无序实体对**：存储时按引用规范化排序，对键与上报方向无关。
同一对实体（含经合并继受解析后的对）存在存续关系时，再次 `relation_proposed` 一律拒绝，
即使两侧顺序相反、或其中一方已更名并入新实体。旧关系终止后，允许为该对登记新的意向关系，
旧对仍完整保留。

同名城市（不同行政隶属但名称相同）在实体卷宗与提议分析中给出 `name_matches` /
`same_name_side` 提示，录入时以稳定标识而非名称为准。

## 5. 行政区更名与合并

- 更名：追加 `name_attached`（`valid_from`、`historical`），实体标识不变。
- 合并：`entity_merged(from, into, effective_date)`。旧实体的既有关系**不移动、不删除**，
  仍以当时实体为缔约方；旧实体卷宗给出 `successor_chain`，现行实体卷宗给出 `predecessors`。
- 合并后系统按现行实体重建配对索引，跨合并的重复配对仍被识别。
- 已合并实体不能再次合并；提议双方经继受指向同一现行实体时拒绝缔结。

## 6. 多语文本与签署版本

`text_recorded` 以 `kind`（`original` 原文 / `translation` 译文）、`language`、`version`
定位一个文本版本；`signed_at` 非空表示该版本为**签署版本**。同语言、同类型、同版本号不得重复；
修订以新版本号追加，旧版本保留。中文正本、日文正本、英文译文可同时存在。

## 7. 路线图约束与城市确认

- 计划分两级：`roadmap`（上级路线图）与 `plan`（下级交往计划，可通过 `parent_ref` 从属路线图）。
- 上级路线图可按**行政隶属链**（国家→省州→城市）挂接（bind）到下级友城关系，
  挂接要求计划实体范围覆盖关系两侧，否则拒绝。
- **挂接不等于城市确认**。约束在城市层面生效必须由城市分别发出 `city_plan_confirmed`；
  卷宗明确列出 `confirmed_by_cities` 与 `pending_cities`。非缔约城市不能确认，未挂接不能确认。

## 8. 承诺、活动成果、逾期与责任部门

- 承诺（`commitment_logged`）按受控类别登记：`culture` 文化、`tourism` 旅游、
  `education` 教育、`youth` 青年、`other`；含责任部门与截止日期（`YYYY-MM-DD`）。
- 承诺可标记兑现（`commitment_fulfilled`）并回指成果活动；允许在关系终止后补录历史事项。
- 活动（`activity_held`）时刻保存**带偏移量的原始字符串**，另存 IANA 时区名
  （如 `Asia/Tokyo`）与多语标题、成果；逾期与排序一律按 UTC 绝对时刻比较，
  跨时区活动不会因展示时区错位。截止日按当天 23:59:59（UTC）判定。
- 友城卷宗汇总：承诺（未到期/逾期/已兑现）、活动成果、**责任部门去重列表**。

## 9. 新合作提议分析

`proposals/analyze` 输入两个实体引用，输出：

- 继受解析结果（`resolved_a/resolved_b`）；
- 冲突：存续关系重复（`duplicate_relation`）、同名混淆（`same_name_side`）、
  继受后同体（`merge_chain`）；
- 可复用资源：两侧各自现有友城网络中尚未兑现的承诺与既有活动，按类别汇总，
  帮助新合作对接既有文化、旅游、教育、青年资源。

## 10. 时间与存储约定

- 日期只有日历语义时用 `YYYY-MM-DD`；时刻一律 RFC 3339 带偏移量。
- 事件日志为单行 JSON（JSONL），路径由 `DATABASE_PATH` 指定，默认 `data/graph-events.jsonl`。
- 材料只保存受控引用与 `sha256` 摘要，不内联敏感文书；示例数据均为虚构。
